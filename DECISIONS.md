# Decisions

- **Authority:** `GAME_DESIGN_DOCUMENT.md` governs gameplay. Locked rules cannot change without user approval; tune values remain unimplemented and unapproved until measured and recorded here.
- **Plan path conflict:** `IMPLEMENTATION_PLAN.md` refers to `docs/` checkpoints, but repository rules prohibit `docs/`. Keep requested checkpoints at the repository root; do not create `docs/`.
- **Test path conflict:** the plan names `Tests/` and `Game.Core.Tests/`; repository rules require lowercase `tests/`. Use `tests/`.
- **Phase mapping:** execute plan phases in order: P0 tooling/bootstrap, P1 full pure simulation, P2 playable graybox. The broader user phase list is mapped within these phases; do not bypass their exit criteria or human gates.
- **Architecture:** authoritative gameplay will be pure C# fixed-step logic, separate from Unity presentation. Do not claim cross-platform bitwise determinism without evidence.
- **Unity target:** pin Unity 6000.3.26f1 (revision de8167e7440c), verified LTS and now installed. The user explicitly confirmed keeping the LTS target during setup. Installed 6000.6.2f1 remains unused for project validation.
- **TUNE baseline:** `CombatTuning.Default` centralizes the GDD numeric starting values. Posture damage rounds to nearest integer, ties away from zero (level 1: 37.5 becomes 38). These are test hypotheses, with no human feel approval.
- **OPEN prototype hypotheses:** 60 Hz; arena 100 x 56.25 units; fighter radius 1.5 and projectile radius 0.6; run speed 12, jump launch 20, projectile speed 24 units/s; parry window 0.10 s; impact recovery delay 0.25 s; spring strength 24 and damping 8. Collider shape and integration coefficients still require P1 implementation/tests. No gameplay rule is implemented by the configuration alone.
- **Clock:** catch-up work is bounded per call but accumulated simulation time is retained. Interpolation exposes only the fractional remainder. Unity's fixed step uses the exact configured tick duration; no authoritative ticks are deliberately skipped.
- **P1 contact order:** continuous circle sweeps merge body/projectile/wall contacts by contact time and stable IDs. Equal-time defense classifications are captured before applying posture/break changes. Resolve all lethal flags across the tick before awarding a round. Body impulses replace residual paths and trigger fresh projectile sweeps; contact overflow fails explicitly.
- **P1 defense TUNE:** valid parry > guard > dash invulnerability > lethal. Dash immunity blocks projectile lethality and body posture damage, while physical body impulse remains; membrane recoil is environmental. Entering guard break cancels dash and immunity immediately. Parry applies only to projectiles.
- **P1 contact lifetime:** guard/parry reflection is one contact until true separation, persisted in snapshot/hash state. Invulnerable pass-through suppression is tick-local so immunity expiry can expose an overlapping projectile. A simultaneous wall/fighter pinch uses deterministic tangent travel as combined contact geometry, with no power-specific steering assistance.
- **P1 TUNE additions:** gravity 60, ground/air acceleration 120/70, friction 150, dash speed 50, released-jump gravity multiplier 2, coyote 0.08 s, jump buffer 0.10 s, dash cancel 0.08 s, guard hold 0.10 s, walking push 3, jump/dash body impulse 14/26, rebound speed 45 with an 18-unit controllable neutral travel budget. Countdown 3 s covers initial spawn warning; round result 1 s; initial fighters at quarter positions, portal inset 2, alternating mirrored 45-degree trajectory. All remain prototype hypotheses.
- **P2 prototype adapter:** Unity fixed ticks feed authoritative numbered inputs; rendered frames buffer action edges. IMGUI/procedural placeholders read state only. A fixed 16:9 playfield fits within safe areas with a separate footer; full fighter collision silhouettes remain visible. The membrane drawing follows its actual full-height collision boundary.
- **P2 debug controls:** Easy/Normal/Hard bot selection changes input policy only, with parity tests. Tuning changes reset the match; captures record applied values, mode, difficulty, tick and checksum. Basic hitstop is 3 ticks on parry and 2 on damaging impacts/break/elimination; ordinary walking contact does not freeze gameplay.
- **P2 tests:** Unity integration tests are a local UPM package under `tests/Unity`, pinned to editor-bundled Test Framework 1.6.0. Offline console tests exclude that subtree. Engine-owned YAML stays canonical; formatting/Git whitespace exceptions apply only to serialized Unity types.
- **Gate A:** technical P2 completion is not subjective approval. Production work remains stopped until explicit human gameplay feedback/approval.
- **Art scope:** no production art before gameplay approval. Preliminary replaceable placeholder anchors and hitbox-independent sprite conventions may be prepared; defer final dimensions and reference-art approval to the art gate.
